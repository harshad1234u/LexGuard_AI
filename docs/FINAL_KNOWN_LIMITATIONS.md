## 1. Purpose and Philosophy of this Document

In legal document intelligence, claiming capabilities that cannot be rigorously guaranteed is a severe safety and liability hazard. LexGuard AI adheres to strict epistemic honesty: **every boundary, unverified field, deferred capability, and provider limitation is documented plainly**.

The limitations listed below are not unresolved bugs; they define the precise operational boundaries of the software.

---

## 2. Upstream Provider Quota & Live Generation Boundaries

### 2.1 Google AI Studio Gemini Free-Tier Quota Limit
- **Observed Behavior:** Google AI Studio free-tier API keys enforce a hard quota ceiling of **20 requests per day per project** (`RESOURCE_EXHAUSTED / 429`).
- **Audit Findings:**
  - Gemini API key authentication succeeds.
  - Gemini model metadata probing (`GET /v1beta/models/...`) succeeds with HTTP 200.
  - Minimal isolated generation probes succeed.
  - Structured JSON schema generation probes succeed.
  - **Full multi-turn live analysis and Q&A:** Blocked when executing across a full document due to cumulative daily free-tier request limits.
- **System Safeguard:** LexGuard AI enforces strict error isolation. When an upstream 429 or 503 occurs, the application stops immediately, logs the exact error code, displays a non-punitive UI alert, and **refuses silent fallback to stub or unauthorized providers**.
- **Operational Requirement for Live Deployment:** Live multi-turn Gemini analysis in production requires either a Google Cloud Vertex AI service account or a Google AI Studio API key with an active billing tier enabled.

### 2.2 NVIDIA NIM Nemotron Live Reasoning Status
- **Current Status:** Tested and operational via NVIDIA NIM (`meta/llama-3.1-70b-instruct` / `nvidia/nemotron-4-340b-instruct`).
- **Operational Boundary:** Nemotron is strictly restricted to secondary cross-finding reasoning notes. It is barred from modifying, approving, or vetoing findings generated by the primary analysis stage.

## 3. UI vs API Surface Discrepancies

### 3.1 `attention` Level is API-Only
- **Backend Capability:** The backend derives an `attention` score (`info`, `review`, `high`) based on concrete contractual terms (e.g. indemnity triggers, short termination windows, uncapped liability).
- **Frontend Presentation:** The current React frontend **does not render visual attention badges** on finding cards.
- **Rationale:** Displaying "high risk" or "review needed" badges easily misleads non-lawyer users into treating the system as a legal risk assessment tool. Findings are organized by neutral legal topic instead.
- **Disclosure:** `attention` must be evaluated as an API-level feature, not a user-facing UI element.

### 3.2 Narrative Explanation is Labelled Interpretation (Unverified)
- **Structure:** Each finding carries a concise `claim` (one sentence) and a narrative `explanation` (1–3 sentences).
- **Verification Asymmetry:**
  - `claim`: Verified against quoted evidence across 8 semantic axes (polarity, modality, actor, conditionality, scope, temporal, numeric, cross-reference). Three known false-negative edge cases are documented in §5.
  - `explanation`: Verified **only for numeric and date consistency**. Full semantic verification of multi-sentence narrative explanations was measured and rejected due to unacceptable false-positive rates (withholding valid explanations).
- **UI Treatment:** Every explanation is rendered with an amber pill: *"Interpretation — not verified against the document"*, and the API sets `explanation_verified: false`.

## 4. Architectural & Document Scope Boundaries

### 4.1 Strictly Single-Document Scope
- **Current Architecture:** LexGuard AI operates on exactly one PDF document per session.
- **Exclusions:**
  - No contract comparison or redlining across two documents.
  - No multi-document workspace or cross-agreement search.
  - No portfolio-wide risk analytics.

### 4.2 Ephemeral Workspace & Database Isolation
- **Storage Strategy:** By default, all uploaded documents, extracted page text, and findings reside exclusively in ephemeral memory (`NullRepository`).
- **Supabase Status:** The Supabase PostgreSQL migration (`supabase/migrations/`) is strictly unapplied in this build. No remote database connection is initiated (`persistence_configured=False`).
- **Privacy Guarantee:** Uploaded contracts are purged upon session termination or when the user clicks "Discard Document".

### 4.3 PDF-Only Ingestion
- **Supported Format:** Valid, text-extractable PDF files under 50MB and 100 pages.
- **Unsupported Formats:** Microsoft Word (`.docx`), plain text (`.txt`), scanned images (`.png`, `.jpg`).
- **OCR Limitation:** Scanned image-only PDFs with no embedded text layer are rejected at the coverage gate rather than subjected to error-prone client-side OCR.

## 5. Semantic & Verification Engine Boundaries

### 5.1 Documented Corpus Edge Cases (`eval_independent.py`)
In extensive independent testing across 75 realistic contract provisions, 3 edge cases resulted in false negatives (attacks released because the modification fell outside the closed vocabulary rules):
1. **Restrictive Condition Carveouts:** *"disputed in good faith"* dropped from *"Invoices disputed in good faith may be withheld"*. (Lacks an explicit conditional conjunction like *if* or *unless*).
2. **Exclusion List Subsets:** Omitting one item from an exclusion list (*wilful misconduct*) while keeping other items intact (*war, nuclear risk*). (The remaining claim is technically a true statement about the policy, though legally narrower).
3. **Reused Numeric Figures:** Fabricating a new obligation in a second sentence while reusing a genuine monetary figure (£5,000,000) that exists elsewhere on the same page.

### 5.2 Contradictory Definition Resolution
- **Detection:** LexGuard AI detects when a document defines the same term twice with conflicting meanings (e.g. "Business Day" in Clause 1.1 vs Clause 14.2). Both double quotes (`"..."`, `“...”`) and single quotes (`'...'`, `‘...’`) are detected.
- **Boundary:** When a conflict is detected, the application **refuses evidence defining that term**. It does not attempt legal construction to decide which clause takes precedence (e.g. later clause vs specific clause). Legal construction is legal reasoning, which this system does not perform.

## 6. Language & Localization Boundaries

### 6.1 Tamil Reading Support
- **Current Capability:** Secondary Tamil translation displayed beside verified English claims and answers.
- **Verification Standard:** Translation is verified for **numeral, percentage, and date consistency** against document evidence.
- **Boundary:** Semantic checking (polarity, modality, role binding) in Tamil grammar is deferred. Other non-English languages are explicitly excluded from this release.

---

## 7. Legal & Regulatory Boundary Statement

LexGuard AI is an **informational tool for document comprehension**, not an attorney or legal advisor:
- It does not provide legal advice, legal opinions, or strategic recommendations.
- It does not generate legal tactics, options, or next steps.
- Verification badges signify **grounding in the uploaded document text**, never legal validity, enforceability, or compliance with governing statutory law.
